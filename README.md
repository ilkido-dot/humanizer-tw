# Humanizer-tw

A Traditional Chinese (Taiwan) adaptation of [blader/humanizer](https://github.com/blader/humanizer). It rewrites AI-sounding zh-TW text so it reads like the writer, without changing what it says.

Humanizer-tw 讓 AI 寫的繁體中文讀起來像作者本人寫的，而且不改變內容。它是英文原版 [blader/humanizer](https://github.com/blader/humanizer) 的台灣繁體中文版，以 Wikipedia 編輯用來抓 AI 文字的指南「[Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing)」為基礎，可以在 Claude、Claude Code、Codex 和其他支援 skill 的工具裡使用。

**改前：**
> 我們很興奮地宣布，共用草稿功能終於來了！🚀 好幾個月來，我們自己的團隊都淹沒在一堆名叫「最終版_v7.docx」的檔案裡——我們知道一定有更好的方法。現在兩個人可以同時編輯同一份文件，每個修改都會即時顯示在雙方眼前。這不只是一個功能，更是一種全新的協作方式。留言會固定在它對應的那一句，就算周圍的文字一直在變也一樣。最棒的是什麼？今天起所有方案都能用，完全免費。好好想想這件事。

**改後：**
> 共用草稿今天上線了。好幾個月來，我們自己的團隊都在傳一堆名叫「最終版_v7.docx」的檔案，所以我們做了一個讓兩個人能同時編輯同一份文件的功能，每個人的修改都會即時出現在對方的畫面上。留言會固定在它對應的那一句，周圍的文字改了也一樣。所有方案都能免費使用。

Humanizer-tw 是為人類讀者改寫。通過 AI 偵測器不是它的目標，它也不保證能通過。

## 五個最強的痕跡

這些是 AI 文字最常見的特徵，Humanizer-tw 看到一次就會改：

1. **不是 X，而是 Y：**「這不只是一個功能，更是一種轉變。」
2. **單句收尾：**「好好想想這句話。」
3. **聽起來很深的格言：**「說到底，真正重要的是……」
4. **預告式鋪陳：**「重點來了。」「老實說？」
5. **跟不存在的人辯論：**「我不是說 X，但……」

Humanizer-tw 總共檢查 [32 個模式](#32-個模式)。

## 安裝

安裝後，用 `/humanizer-tw` 呼叫。

### Claude.ai 與 Claude 桌面版

1. 在這個頁面按 **Code → Download ZIP**。
2. 到 Claude 的 **Customize → Skills**，按 **+**，選 **Create skill → Upload a skill**，上傳剛下載的 ZIP。
3. 上傳後把它的開關打開。

需要先在 **Settings → Capabilities** 打開 **Code execution and file creation**。如果上傳失敗，把 ZIP 解壓縮，把資料夾改名為 `humanizer-tw`，再重新壓縮上傳。

### Claude Code

```text
/plugin marketplace add ilkido-dot/Humanizer-tw
/plugin install humanizer-tw@humanizer-tw
```

plugin 用 `/humanizer-tw:humanizer-tw` 呼叫。需要 Claude Code 2.1.142 以上；較舊的版本請用 `npx skills add ilkido-dot/Humanizer-tw --global --agent claude-code`。

### Codex

```bash
npx skills add ilkido-dot/Humanizer-tw --global --agent codex
```

### 其他工具

```bash
npx skills add ilkido-dot/Humanizer-tw --global --agent '*'
```

這會替 Skills CLI 支援的所有工具安裝，包括 Gemini CLI、GitHub Copilot 和 Windsurf。上面任何一個指令拿掉 `--global`，就只裝在目前的專案。Skills CLI 不認得的工具，把 `SKILL.md` 複製到它的 skill 資料夾即可。

## 使用方式

直接呼叫：

```
/humanizer-tw

[貼上你的文字]
```

或用一般的話說：

```
請幫我去掉這段文字的 AI 味：[你的文字]
```

改寫檔案時，給它路徑：

```
幫我改寫 docs/新品介紹.md 的文字
```

預設會交回初稿、剩下的問題和最終版。只想要結果的話，加一句「只給我最終版」。

### 配合你的語氣

想讓改寫更像你，就附上範本：

```
/humanizer-tw

這是我自己寫的文字，請照這個語氣：
[貼上兩三段你自己寫的文字]

現在幫我改寫這段：
[貼上 AI 寫的文字]
```

Humanizer-tw 會跟著範本的節奏、用詞、標點和刻意的小習慣，包括你有用破折號的話也會保留。

## 運作原理

語言模型寫的是最可能接在後面的字，所以預設會選一個適用於最多讀者、最多題材的寫法。人寫作時是為一個讀者、一個題材做選擇。Humanizer-tw 找的每一個痕跡，都是這種預設選擇的一種形式：在宣告重要而不是提供事實的句子、照規則套用的節奏或排版、被包裝成關鍵的普通事實、聊天留下的殘留，以及重新解釋讀者早就知道的事的回覆。

> "LLMs use statistical algorithms to guess what should come next. The result tends toward the most statistically likely result that applies to the widest variety of cases."
> Wikipedia，「[Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing)」

Humanizer-tw 會從最強的痕跡開始，標出找到的每一個。它寫初稿時不把原本的結構當成固定的，再對照模式和原文的主張檢查初稿，最後寫出最終版。它不編造東西：名字、數字、日期、引文、出處和其他事實細節，都必須來自原文或作者；某句需要原文沒有的細節時，它會問你，而不是自己編一個。

改寫檔案時，它只改文章內容，程式碼、資料、YAML 和連結目標保持不變。個人文字保留作者的看法和小習慣；技術與參考文字維持中性平實。

## 32 個模式

模式依強度和頻率排序。前五個看到一次就值得改。標示「*單獨出現不算*」的模式，要在同一段有好幾個痕跡時才算，因為細心的作者可能刻意使用其中任何一個。§1 到 §26 與英文原版同號；G、H 兩組是台灣版新增。

### A. 鋪陳取代陳述

| # | 模式 | 改前 | 改後 |
|---|------|------|------|
| 1 | **不是 X，而是 Y** | 「這不只是 X，更是 Y」、「這不代表 X。這代表 Y。」 | 直接說出重點 |
| 2 | **單句收尾與戲劇性碎句** | 每一節後面都接「這才是真正的關鍵。」；例子後面補「這說明了……的重要性」；「沒有預設。沒有包袱。」 | 刪掉重複或解釋例子的收尾；把碎句合併成具體的主張 |
| 3 | **聽起來很深的格言** | 「說到底，真正重要的是……」、「對稱是信任的語言」 | 把格言換成具體的主張 |
| 4 | **重點之前的預告式鋪陳** | 「讓我們深入看看」、「在當今……的時代」、「老實說？要看……」 | 刪掉鋪陳，直接說重點 |
| 5 | **跟不存在的人辯論** | 「這主要不是在講……」、「一個誘人的做法是……」 | 刪掉沒人提過的反對意見或假選項；保留真正的主張 |

### B. 照規則的節奏

| # | 模式 | 改前 | 改後 |
|---|------|------|------|
| 6 | **硬湊三點** | 「創新、啟發與洞見」；三個例子加一句教訓 | 意思需要幾項就寫幾項 |
| 7 | **重複的句子開頭** | 「她注意到……她注意到……她把……」 | 合併句子或換主詞 |
| 8 | **把破折號當萬用連接**（*單獨出現不算*） | 「新政策——事前毫無預告——影響了……」 | 改用句號、逗號、冒號或括號；範本有用破折號就跟著用 |
| 9 | **層層疊加的限定詞**（*單獨出現不算*） | 「或許可以說，某種程度上可能會……」 | 只保留原文支持的限定詞 |
| 10 | **術語後面硬加括號英文**（*單獨出現不算*） | 「OKR（Objectives and Key Results）」反覆出現 | 第一次出現時附一次就好 |
| 11 | **被動語態與缺少主詞**（*單獨出現不算*） | 「結果會被自動保存」 | 有助於理解時寫出動作者 |

### C. 誇大與借來的權威

| # | 模式 | 改前 | 改後 |
|---|------|------|------|
| 12 | **AI 常用詞** | 「此外……值得一提的是……版圖……見證……彰顯」 | 用平實的詞 |
| 13 | **誇大的意義** | 「標誌著關鍵時刻」、「儘管面臨挑戰，依然蓬勃發展」、「未來可期」 | 保留事實，拿掉意義；在最後一個具體事實結束 |
| 14 | **模糊的關聯** | 「與該公司的領導層有關」 | 寫出原文給的關係 |
| 15 | **句尾附加的空洞補充** | 「，象徵著……，體現了……」 | 只保留原文支持的部分 |
| 16 | **廣告腔** | 「坐落於群山環抱之中、景色令人嘆為觀止」 | 直接說那是什麼 |
| 17 | **借來的權威** | 「專家認為……」、「曾登上多家國際媒體」 | 寫出真正的來源和說法，或刪掉主張或清單 |
| 18 | **迴避「是」和「有」** | 「作為……設有……坐擁……」 | 「是……有……」 |

### D. 照規則的排版

| # | 模式 | 改前 | 改後 |
|---|------|------|------|
| 19 | **把粗體當裝飾** | 「**效能：** 效能提升了」 | 拿掉粗體；把標籤清單改寫成段落 |
| 20 | **裝飾性標題** | 「🚀 上市階段：」、「一張圖看懂決策」 | 拿掉 emoji 和箭頭；標題說出這一節有什麼 |
| 21 | **引號與標點**（*單獨出現不算*） | `他說“這批苗況很好”,但……` | `他說「這批苗況很好」，但……` |

### E. 聊天與草稿的殘留

| # | 模式 | 改前 | 改後 |
|---|------|------|------|
| 22 | **聊天機器人的殘留** | 「好問題！……希望這對你有幫助！」 | 拿掉外殼，保留內容 |
| 23 | **知識範圍的免責與猜測** | 「雖然具體細節有限，但看起來……」 | 寫出原文呈現了什麼，或刪掉這句 |
| 24 | **第一句重複標題** | 「## 效能」接「速度很重要。」 | 讓標題自己說話 |
| 25 | **寫文件本身，而不是寫主題** | 「新增這個函式是為了取代……」、「本文整理自……」、「下表比較了……」 | 描述主題；讀者看不出來的慣例才說明 |

### F. 寫錯讀者

| # | 模式 | 改前 | 改後 |
|---|------|------|------|
| 26 | **重新解釋讀者已經知道的事** | 一則回覆先走完診斷、證明計畫可行，最後才講決定 | 先講決定；診斷和證明留給後續的工單或文件 |

### G. 中文特有的句型（台灣版新增）

| # | 模式 | 改前 | 改後 |
|---|------|------|------|
| 27 | **名詞化的動詞**（*單獨出現不算*） | 「對這批苗進行換盆」、「做出決定」 | 「幫這批苗換盆」、「決定」 |
| 28 | **疊在一起的「的」**（*單獨出現不算*） | 「適合新手的耐陰的室內的品種」 | 把修飾語拆成短句 |
| 29 | **四字詞堆疊**（*單獨出現不算*） | 「透氣排水、輕巧方便、經濟實惠、值得信賴」 | 保留有具體意思的，刪掉空泛重疊的 |
| 30 | **照英文結構翻過來的句子**（*單獨出現不算*） | 「對於新手來說，在光線不足的情況下，會是一個挑戰」 | 拿掉框架，讓主詞和動詞直接出現 |

### H. 台灣用語與字形（台灣版新增）

| # | 模式 | 改前 | 改後 |
|---|------|------|------|
| 31 | **混入的大陸用語** | 「視頻的質量」、「默認設定」 | 「影片的品質」、「預設設定」 |
| 32 | **繁簡轉換留下的字** | 「爲了」、「裏面」、「着想」 | 「為了」、「裡面」、「著想」 |

## 完整範例

**改前（像 AI 寫的）：**
> 去年十月，我在台南度過了難忘的五天，不得不說，這座城市完全擄獲了我的心。從我入住位於神農街、充滿復古魅力的民宿那一刻起，我就知道自己來到了一個非常特別的地方。
>
> 沒錯，台南很熱——就算十月也一樣，我每天都滿身大汗！——但每一條小巷都會用令人驚豔的老屋風景回報你，讓一切都值得。
>
> 來台南怎麼能不吃牛肉湯？凌晨五點的排隊人潮裡，滿是迫不及待想品嘗美味的旅人。至於小吃？簡直是天堂。雖然國華街的小吃是大家公認的經典，但我的最愛是巷子裡一家隱藏版的碗粿，剛蒸好還冒著熱氣。
>
> 但台南真正特別的地方，不只是景點，更是那種感覺。從熱鬧的大街往巷子裡多走一兩條，你就會發現一個更安靜、更道地的台南，邀請你放慢腳步，細細品味每一刻。
>
> 當然，必訪的赤崁樓有著令人嘆為觀止的古蹟建築。雖然排隊人潮不少，但對任何歷史迷或好奇的旅人來說，這趟體驗絕對值回票價。
>
> 我會再去嗎？當然會——下次要挑冬天，還要帶一把扇子！台南不只是一個旅遊的地方，更是一個會讓你一再愛上的地方。✨

**改後：**
> 去年十月我在台南待了五天，住在神農街的一間民宿。十月還是很熱，我每天都滿身大汗，不過巷子裡的老屋很好看，走起來值得。
>
> 大家都說要吃牛肉湯，所以我去了。凌晨五點就要排隊，排隊的幾乎都是觀光客。國華街的小吃很有名，但我最喜歡的是巷子裡一家碗粿，剛蒸好還冒著熱氣。
>
> 我最喜歡的台南，是從大街往巷子裡多走一兩條的地方，那裡很安靜，大家都不趕時間。赤崁樓的古蹟建築很好看，排隊的人也不少。
>
> 我會再去，下次挑冬天，還要帶一把扇子。

## 跟英文原版的差異

| 項目 | 英文原版 | Humanizer-tw |
|------|----------|--------------|
| 語言 | 英文 | 台灣繁體中文 |
| 模式數 | 26 | 32：§1 到 §26 同號對應，另加 G、H 兩組 |
| §10 | 連字號複合詞 | 術語後面硬加括號英文 |
| §21 | 彎引號改成直引號 | 改成「」和全形標點 |
| 觀察清單 | 英文的 AI 用語 | 中文的 AI 用語 |
| 範例 | 英文情境 | 中文情境，部分改成台灣的例子；改後版本都不新增資訊、不改變數量 |
| 新增規則 | | 簡體原文先問使用者要不要轉換；台灣常見文體（IG、短影音、email、商品介紹、預測）的語氣補充 |
| 工具 | `validate-package.py` | 另加 `check-zh-tw.py` |

## 檢查工具：check-zh-tw

`scripts/check-zh-tw.py` 會檢查文字裡的簡體字、繁簡轉換留下的字、中文裡的半形標點與彎引號，以及大陸用語。只需要 Python 3，不用安裝任何套件。

```bash
python3 scripts/check-zh-tw.py 你的文字.md
```

```
你的文字.md:2:12  錯誤［殘留字形］「爲」  改成「為」
你的文字.md:3:5   提醒［大陸用語］「視頻」  台灣通常說「影片」
```

字形和標點問題算錯誤，會讓程式以失敗結束。大陸用語只是提醒，因為同一個詞換個語境可能沒錯，例如物理上的「質量」；加上 `--strict` 時也算錯誤。程式碼區塊、行內程式碼、網址和 hashtag 不檢查。
